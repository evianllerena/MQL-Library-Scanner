==============================================================================
0. SCOPE -- WHAT THIS BACKTESTER IS, AND WHAT IT DELIBERATELY IS NOT
==============================================================================
[RB] was written for a multi-timeframe LIVE EA. This project is a DAILY,
single-candidate, indicator-RANKING backtester: it extracts real indicator
values from MT5 with CopyBuffer, then nnfx_engine.py replays the rules bar by
bar. It is NOT the Strategy Tester and NOT a live EA.

We port the TRADING RULES (anything that changes which trades fire or how they
exit, and therefore changes a candidate's ranking). We do NOT port EA
architecture.

IN SCOPE
  Entries E0-E6, exits X1-X4, trade management T1-T4, money management
  M1-M5 (as they affect pips/equity), signal semantics (zero_reference, no
  OB/OS), volume filter, bridge-too-far, R1 drawdown (metric + circuit
  breaker).

IN SCOPE, DORMANT (built, OFF until data exists)
  N1 / X5 news rules -- off until a ForexFactory high-impact calendar file
  is loaded (Section 8).

OUT OF SCOPE -- NOT MISSING WORK (do not build; see Section 11)
  Multi-timeframe (30M/1H/4H); rollover entry window (M9, Decision 10);
  shared currency exposure (M6/M7); dead-market filter (D1/D2, T6) --
  real NNFX rules, user may opt in later; three-EA architecture; broker lot
  rounding; hedging vs netting; position recovery after restart; runner cap
  (T7, Decision 11 unticked); pair universe (P1/P2) -- set by the batch's
  --bed-symbols, not by the engine; N2 elections; N3 is satisfied by N1/X5
  once the calendar exists.

5. EXITS AND TRADE MANAGEMENT
==============================================================================
Exit precedence: whichever fires first closes what is left. X2, X3 and X4 are
each a setting, all ON by default (Decision 2, +U).
Engine order per bar: SL -> TP1 (half 1) -> trail update -> X3/X2/X4 on the
remaining position, evaluated on the bar's close.

X1 (A) Stop loss 1.5xATR from entry; TP1 at 1.0xATR closes half 1; then the
   runner's stop moves to breakeven; then it trails (T4).
                                                     Src: Scaling Out; Risk
                                                     Management guide
                                                     Status: CURRENT (trail
                                                     timing changes in FIX 6)

X2 (A slot / B mechanics) EXIT INDICATOR signals against the trade -> close
   what is left. Direction is read against the exit indicator's OWN
   zero_reference -- never "> 0 / < 0".              Src: VP Volume post;
                                                     flow charts
                                                     Status: FIX 2
   Setting: enable_exit_indicator = True (with no exit indicator supplied,
   behaviour is identical to today).
   T5 (A): the exit indicator "competes with" the trailing stop -- both run;
   whichever closes the runner first wins.           Src: Backtesting Ep.21

X3 (A implied) C1 gives an opposite signal -> close what is left.
   "If your own Confirmation Indicator is giving you a short signal before
   your Exit Indicator tells you to abort ... Why are you still in the
   trade?"                                           Src: Scaling In Ep.25
                                                     Status: CURRENT
   Setting: enable_c1_flip_exit = True

X4 (B) Price CLOSES on the wrong side of the baseline -> close what is left.
                                                     Src: flow charts; Algo
                                                     Tester (optional there)
                                                     Status: FIX 1 (today a
                                                     wrong-side close only
                                                     resets continuation; it
                                                     does not exit)
   Setting: enable_baseline_exit = True

X5 news exit -- see Section 8.

T1 (A) Two equal halves, same 1.5xATR stop; half 1 has TP at 1.0xATR.
                                                     Src: Scaling Out
                                                     Status: CURRENT
T2 (A) When half 1 hits TP1, the runner's stop moves to breakeven (entry).
                                                     Src: Scaling Out
                                                     Status: CURRENT
T3 (A) Runner has no fixed target ("let that baby run").
                                                     Src: Scaling Out
                                                     Status: CURRENT
T4 (B+U, Decision 1) TRAILING STOP on the runner: 1.5xATR behind price,
   switched ON only once price has CLOSED 2xATR beyond entry, moved once per
   candle close, never backwards.                    Src: No Nonsense Trader
                                                     -- Trailing Stop
                                                     Status: FIX 6 (today it
                                                     trails from the bar TP1
                                                     is hit, i.e. as soon as
                                                     a close is 1.5xATR past
                                                     entry)
   Settings: trail_activate_atr = 2.0, trail_distance_atr = 1.5,
             trail_step = 'per_candle'
   Recorded conflict: the Rui Silva flow chart moves the trail in 0.5xATR
   steps; the lesson site moves it daily at 1.5xATR. Default = lesson site.


==============================================================================
6. CONTINUATION (E6)  -- CORRECTION TO THE CURRENT ENGINE
==============================================================================
After an exit, re-enter in the SAME direction as the original trade.

Common conditions, both versions (B+U, Decision 7):
  - price has NOT closed across the baseline since the ORIGINAL entry;
  - IGNORE the volume filter and the 1xATR rule;
  - money management unchanged (same SL/TP1/halves/trail).

Version (a) VP (B+U, Decision 6; per the user, from VP's videos) -- DEFAULT:
  C2 flips back in the trade's direction AND C1 has never flipped against
  the trade since the original entry.
Version (b) Lesson 11 (B; the lesson author's own design, not VP's):
  the EXIT indicator flips back in the trade's direction and doubles as the
  continuation signal.
  Setting: continuation_mode = 'vp_c2' (default) | 'lesson11_exit'
  Both are backtested; the user picks the permanent default from results.

Current engine (to be corrected in FIX 5): continuation fires on a fresh C1
signal in the trade's direction (with C2 required to agree). That is neither
version above.

KEEP (already correct, regression-tested): the whipsaw reset -- once price
closes on the opposite side of the baseline, continuation eligibility is lost
and only a genuine standard entry can re-arm it (a bare cross with no trade
behind it never does).
                                                     Src: flow charts;
                                                     Lesson 11
                                                     Status: FIX 5

7. VOLUME FILTER (slot 5)
==============================================================================
V1 (A) Volume/volatility is a pass/fail filter for standard entries
   (ignored by continuation).                        Src: VP Volume post
V2 (design choice, not a VP rule) Pass rule held identical for every
   candidate so the ranking is fair: today's reading >= its own 20-bar
   average x volume_threshold_mult (1.0). Today's value and its average MUST
   come from the SAME configured indicator line.
   Status: FIX 3. Today:
     - G9: for every candidate that is not itself a VOLUME candidate, the
       backdrop has no volume indicator and the filter always passes
       (volume_value=1.0, volume_avg=0.5 hardcoded in score_candidate).
     - G10: NNFXHarness.mq5 VolumePasses() averages buffer 0 even when
       today's value comes from a different buffer, so it can compare two
       different lines. (The Python VOLUME path already averages the same
       line.)
   FIX 3 adds a real reference volume indicator to the backdrop and makes
   the harness read value and average from the same buffer.

10. DRAWDOWN (R1, Decision 12)
==============================================================================
R1 (A+U) Aim for no more than 10% maximum drawdown; 15% is "a lot"; 20% is
   "Armageddon".                                     Src: Forex Drawdown
                                                     Ep.52

(a) METRIC: max_drawdown per candidate stays a leaderboard column.
    >>> FINDING TO FIX (7b-a): today's max_drawdown is in PIPS, and it is
        computed over the trades of every symbol CONCATENATED one symbol
        after another (EURUSD's trades, then GBPUSD's, ...), not in date
        order, and not as a % of equity. That cannot be compared with R1's
        10%. FIX 7b keeps the pips column for continuity and adds
        max_drawdown_pct: the peak-to-trough % of an equity curve built
        chronologically across the basket at risk_pct per trade (M2/M4).

(b) CIRCUIT BREAKER: during the simulation, track the candidate's running
    equity. Once equity is >= dd_breaker_pct below its peak, STOP opening
    new trades (standard and continuation). Open trades keep their stops
    and exits. Resume opening trades when drawdown is back under the
    threshold.
    Settings: enable_dd_breaker = True, dd_breaker_pct = 10.0,
              dd_resume_rule = 'below_threshold'
    >>> USER-CONFIRM ITEM: the RESUME condition. Default "drawdown back
        under the threshold" is a placeholder; [RB] only says when to stop.
        The breaker counts skipped entries (skip:dd_breaker) so the effect
        is visible.
                                                     Status: FIX 7b
